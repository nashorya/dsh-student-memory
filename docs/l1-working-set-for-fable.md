## 1. 核心主张（措辞已修订）

**模型每轮只看见 L1。** L2 / L3 / 会话日志都是后面的库，东西按需搬进 L1，不并排给模型读。

v1 的第一句话改了：不再是「L3 由模型看完 L2 再选」。改成——**出错时把候选摊到模型面前，认不认由模型判**。规则只做门卫：收短菜单、看住写入纪律；规则不认亲、不枚举情况。

---

## 2. 已拍定的结论

讨论中已收口、不再重开的：

1. **单通道。** L1/L2/L3 三路 `systemPrompt.context` 收成一路 L1；取消 `L3_CONTEXT` 独立注入。
2. **L0 只留真规则。** write_lesson 合同这类指令留 system；`openArcs`、催收提示、水印是逐轮动态量，移出 system，保住 `CACHE_PREFIX_BREAKPOINT` 的静态前缀。催收原文同时不得出现在产品面。
3. **gene 不做。** 只有 lesson。正向经验的需求真撞上来时，先考虑放宽 lesson 来源约束，不立新类型。
4. **Memorix / embedding v1 不接。** 换 embedding 的信号：库过百条、复盘发现同根因不同措辞的漏检集中出现、lesson 中英混写导致词法失效。真换时做混合检索，精确 token 通道保留。
5. **L2 摘要用结构字段渲染。** 不再叫一次模型写摘要。L2 的真瓶颈在写入：需要给模型写 L2 的工具（workingMemory / taskLedger / 否定过的假设），否则摘要永远是空表。
6. **lesson 的单位。** 模型写的一段短因果：cause、fixPattern、contrast、doNotApplyWhen，外加一句「这是在说什么」（与 cause 第一句同层，不是新对象）。像一条好 skill——短、窄、能再用——但不是 skill，不改名、不按 skill 库设计。禁止把「接着调用了 X」写成 fixPattern。
7. **规则不枚举情况。** 这是 student-agent 已付学费的结论：规则代写 lesson（做错了→调了什么工具）产出全废。推论：规则不代写正文、不建「情况 → lesson」映射表、不宣布「这就是那一种」。错误码对照表、applyWhen 清单、errorSignature→工具映射，都算枚举。
8. **召回的形态按库规模走。** 几十条以内：出错时把全部（或松检索收短后的）lesson 短介绍摊开，模型直接认，不需要精确匹配器。几百条以后：先摊类的短介绍，认准一类再看该类下的几条。中间没有魔法数字，菜单认不过来了再上类。
9. **分类（如果做）的纪律。** 归类由模型做：先拉已有类目，合适则归，不合适才开新类；开新类必须贵（说不清和最近旧类的差别就归旧类）。规则不代填类名。类是文件夹，不是匹配主键。
10. **召回宁松勿严，条数封顶。** 误召的代价是几十 token，漏召的代价是再踩一次坑。摊给模型的候选封顶 3–5 条；库空时 L1 里就是没有经验块，这是正确的空。
11. **产品面不提 L1/L2/L3。** 用户看：目标、ADR+Todo、刚做了什么、学到了什么（有无测试背书）、这轮用上了哪条旧经验。原型里「L1 舵手区」这类命名要在落 UI 前改掉。

## 3. 各层是什么

| 层 | 是什么 | 模型默认看见吗 |
|---|---|---|
| L1 | 这一拍的工作集 | **只看这个** |
| L2 | 当前任务钉住的状态库 | 不看全文。每轮一份结构渲染的摘要进 L1；不够再取明细补进 L1 |
| L3 | 过去的经验库（lesson） | 不看。出错时摊进 L1 的候选才可见 |
| 日志 / 文件 | 旧对话原文、完整工具输出 | 默认不在。点名再读，读完只进这一轮 L1 |
| 规则（现 L0） | write_lesson 合同等指令 | 留在 system，静态；动态量全部搬走 |

「一轮」沿用 dsh 的 turn（turn/start 到 turn/end，中间多个 step 同轮）。旧轮次 surface 摘掉；状态要跨轮活下去，必须已在 L2 库里或已写成 lesson。

## 4. 装填规则

```
每轮装配 L1
  ├─ 目标 / 步骤 / 硬约束        ← 核心块，保底
  ├─ L2 摘要（结构渲染）          ← 默认放入
  ├─ 催收/弧状态（从 L0 搬来）    ← 有开放弧才出现
  ├─ 出错时摊开的 lesson 候选     ← 新开弧那一拍注入，模型认亲
  ├─ L2 明细 / 日志原文           ← 模型点名才放入
  └─ 预算仲裁                    ← 见第 8.5，未拍
```

召回触发只有一个：`observeTool` 新开弧的那一次。不每轮扫描、不跟用户原话、不用 `refreshRecall(liveQuery)`。同轮后续 step 重新装配时能看到候选；跨轮不缓存（turn 末尾出错的丢失问题见 8.6）。

候选卡片 = 「这是在说什么」一句 + doNotApplyWhen 一行 + id。全文不进；模型要细节走取数。用没用由模型判，规则不写「请使用 lesson_x」。

## 5. 写入

写路径本来就是模型经 `write_lesson` 写的（旧 student-agent 的规则代写病不在本插件）。规则保留的职责：

- 开弧、把报错原文存成附件（`Arc.errorText`，是否进召回键见 8.3）
- 校验（开放 arcId、非空 cause/fix）
- trust 标注（成色问题见 8.4）

明确不做：规则从轨迹合成 lesson 正文；为凑收割降低校验；必填 applyWhen。

## 6. 现状与缺口（对着代码说）

钉死 dsh `47f9438`。截至本稿：

- L1/L2/L3 仍三路并排注入（`index.ts` order 200/210/220）；L2 无字符预算。
- `refreshRecall` 无人调用——召回触发根本没接线，谈算法为时过早。
- `Arc` 只存 `openedBy`，报错原文不落盘；`moves` 只有 `"bash error"` 这种工具名，当不了任何召回键。
- `classifyObservation` 用正则枚举工具名定 trust（参数带 "test" 的成功调用就记 `tests-green`；跑一次 eslint 算 `tsc-ci`；测试失败但工具调用本身不报错也可能记绿）。**这与第 2.7 条的反枚举原则直接冲突**，而 trust 又被提议承担筛选职责。见 8.4。
- 弧的错-改配对是启发式（绿灯挂最近开弧），并发多弧会配错亲。
- `MemoryStore` 形状在，runtime 未接。
- 收割提示（`HARVEST_PROMPT`）在审阅轮被以误诊为由拆除，拆除后写入无任何触发。见 8.1。

## 8. 待拍的事（v1 动手前必须清）

替换 v1 稿的六个旧问题。前两条不拍，本计划不存在。

1. **写入触发。** 催收被拆的理由（模型为交差写空话）已被证伪，但没人回补。不催收 + 模型不会主动写 + 出错才召回 = 永远空转。候选方案：只在「弧被 tests-green/tsc 关合」那一刻提醒一次（信号最强、频率最低），而不是每轮催。要拍：恢复哪种催收，还是接受手动写入。
2. **isolated 的地位。** 「isolated 不沉底（新近有价值）」与「isolated 不参与召回」两句都在记录里，直接冲突。倾向：本会话内的 isolated 可召回，跨会话降权或排除。要拍。
3. **匹配键。** 三个版本并存：报错原文撞 `errorSignature`；报错对正文松检索；短介绍直接摊开。几十条规模下第三个最简单，且意味着 `errorSignature` 字段 v1 不需要。倾向：`Arc.errorText` 照存（成本低、日后要用），召回 v1 只做摊开或最松的收短，不做签名精确匹配。要拍。
4. **trust 判定的地基。** `classifyObservation` 的正则枚举修不修。两个出路：接 dsh 的结构化工具结果判断测试真绿（贵），或把 trust 降级为纯展示标签、不承担任何筛选职责（便宜）。v1 倾向后者。要拍。
5. **L1 预算仲裁。** 单通道后目标/硬约束、L2 摘要、催收、候选卡片、拉取物抢同一份 `DEFAULT_L1_BUDGET = 2000`。要定：核心块保底多少、卡片和 L2 摘要谁让谁、催收能不能挤占任务规格。审阅轮提出至今无人回答。
6. **验收。** 早先「20 条报错对照表」适配的是检索命中率，摊开方案下要改验的是「模型拿短介绍能否该用时用、不该用时不用」——只能靠少量真实轨迹回放。要定回放的最小形式，否则一切「更好了」都是修辞。
7. **取数工具形状。**（从 v1 稿顺延，优先级最低）一个 `fetch_context(kind, query, id)` 还是分开。看一次真实轨迹再定，现在不拍死。
